# 图片校验机制 · 设计说明

> 本文是 `travel-roadbook-pipeline` 中「五道闸门」的设计依据与调参指南。
> 起因：一次真实交付中，用户明确指出 **"搜索下载的图片未经校验即放入页面、导致大量错误"**。

## 一、问题溯源

### 1.1 旧代码的全部"校验"

```python
# .build/fetch_photos.py
def pick_urls(html, limit=6):
    """取笔记封面图（排除头像）"""
    out = []
    for m in re.finditer(r'https://sns-webpic-qc\.xhscdn\.com/[^\s"\'<>\\]+', html):
        u = m.group(0).replace('&amp;', '&')
        if u not in out:
            out.append(u)
        if len(out) >= limit:
            break
    return out
```

**"校验" = 域名是小红书 CDN + 去重。** 然后 `--pick N` 盲取第 N 张。

### 1.2 这段代码无法回答的问题

| 问题 | 后果 |
|---|---|
| 图是美食还是景点？ | `cat` 字段是人工填的，图是盲取的 —— 两者无约束 |
| 是不是博主头像 / 攻略长图 / 截图 / 地图？ | 实测首轮 **d09/d10 抓到攻略信息图** |
| 图里到底是不是目标 POI？ | 博主常配无关图，无从判断 |
| 是否已 404 / 防盗链占位图？ | `--pick` 不看返回内容 |
| 宽高比是否长图拼接（1:5）？ | 裁 3:4 后只剩一条缝 |

### 1.3 结构性缺陷：命名与元数据无互锁

实证错位：**某天的景点图（`cat=sight`）被存成了 `photos/dNN-food.webp`**。

根因：流程是「先取图落盘 → 后填 `photos.json`」，命名时还不知道内容该属于哪个分类。
一旦命名与语义分家，错位就是必然。

## 二、五道闸门设计

### 闸门 ① 有效性

| 判据 | 阈值 | 拦什么 |
|---|---|---|
| `naturalWidth > 0` | — | 破图、未加载、防盗链 |
| 文件字节 | ≥ 20 KB | CDN 的 1×1 占位图、错误响应体 |
| HTTP 状态 | < 400 | 失效链接 |
| 非头像元素 | — | `closest('[class*=avatar]')` 命中即淘汰 |

**为什么字节阈值重要**：防盗链通常返回一个极小的占位图（几百字节）而不是 403，
只查 HTTP 状态会漏。

### 闸门 ② 尺寸合理性

| 判据 | 阈值 | 拦什么 |
|---|---|---|
| 最短边 | ≥ 480 px | 缩略图、表情、小图标 |
| 宽高比 | 0.5 ≤ w/h ≤ 2.0 | 长图拼接（1:5）、超宽横条 |

**为什么上限是 2.0**：路书图位是 3:4（0.75）竖版。宽高比 > 2 的图裁进来会损失
大半画面，视觉上是"一条横带"，不如不放。下限 0.5 同理（1:2 竖图裁切尚可接受）。

### 闸门 ③ 素材类型判别

两类拦截：

**(a) 关键词拦截** —— 邻近文案命中头像/图标词表：

```
头像 / avatar / logo / icon / 二维码 / qrcode / 水印
```

**(b) 攻略信息图拦截** —— 邻近文案命中 **≥2 个**"信息图词"：

```
攻略 / 行程单 / 清单 / 价格表 / 门票价格 / 时间表 / 路线图 / 地图 /
导航截图 / 表格 / 汇总 / 防坑 / 指南 / 避雷 /
关注我 / 点赞 / 收藏 / 私信 / 评论区 / 同款 / 链接
```

> **为什么要求 ≥2 个**：单个词容易误伤。博主正文里出现一次"攻略"是常态；
> 同时出现"行程清单 + 价格表 + 汇总"才是真的信息图。

**(c) 文字密度兜底** —— 若能从 `evaluate` 拿到图上文字覆盖比例（需额外做一次
canvas 采样或 OCR），`text_ratio > 0.35` 判为信息图。**默认关闭**（成本高），
仅在词表拦截失效时启用。

### 闸门 ④ 语义一致性（**最值钱的一道**）

**核心思想：用图片的"邻居"证明图片的身份。**

小红书笔记页里，图片上下方的文案、图片的 `alt`、笔记标题 —— 这三处文本就是
这张图的语义证据。**比看 URL 可靠一万倍。**

三条子规则：

**(1) 必须有 POI 核心词命中**

```python
kws = ["<该 POI 的专名>"]   # 来自该 POI 本身，不是泛描述
hay = near + alt + note_title
hit = [k for k in kws if k in hay]
if not hit: → 淘汰
```

**(2) 不能只命中泛词** —— 泛词黑名单：

```
旅行 / 旅游 / 攻略 / 拍照 / 打卡 / 风景 / 美食 / 推荐 /
一日游 / 自驾 / 路线 / 分享 / 记录 / vlog / 日常
```

若 `hit` 里全是泛词 → 淘汰。**否则任何一张旅行图都能通过"旅行"这个词过关。**

**(3) 分类词族校验** —— 防止"菜单图配给景点位"：

| `cat` | 必须命中的词族 |
|---|---|
| `food` | 吃 / 餐 / 菜 / 粉 / 面 / 汤 / 肉 / 饼 / 饭 / 酒 / 茶 / 小吃 / 火锅 / 烧烤 / 奶茶 / 甜品 / 早 / 夜宵 / 食 |
| `sight` | 景 / 湖 / 山 / 寺 / 窟 / 塔 / 城 / 宫 / 公园 / 遗址 / 博物馆 / 古镇 / 峡谷 / 丹霞 / 雅丹 / 日落 / 日出 / 夜 |
| `stay` | 酒店 / 民宿 / 客栈 / 住宿 / 房间 / 床位 |
| `charge` | 充电 / 充电桩 / 超充 / 补能 / 换电 |

> **注意**：词族是"宽松命中"（任一即可），不是全部必须。目的是排除跨类别错配。

### 闸门 ⑤ 落盘命名断言

```python
expect = 'photos/d%02d-%s.webp' % (day, cat)
if img != expect: → 淘汰
```

**这是消除 1.3 节那个结构性缺陷的关键** —— 命名由 `(day, cat)` 唯一决定，
写盘前先断言，错位就不可能发生。**命名与语义校验共用同一份 `cat` 定义。**

## 三、失败降级三级

```
① 有合格图
   → 落盘 photos/d{天:02d}-{cat}.webp，附笔记直链

② 无合格图
   → 换更精确关键词重搜
     实证：从"某地"细化到"某地 具体地标/机位名"能有效救回该天的图

③ 仍无合格图
   → 该位不放图，记入 skip 报告
     页面自然收窄（不占位、不破版），绝不硬塞一张错图

④ 用户想补
   → 按 图片替换/D{天}-{类型}-{名称}.png 丢文件，自动识别替换
```

**原则：宁可少一张图，不要多一张错图。** 错图的伤害（读者一眼看出"这不是这个景点"）
远大于缺图。

## 四、用户手选图通道（命名约定）

旧 `replace_photos.py` 里是硬编码的 11 条 MAP：

```python
# ❌ 旧做法 —— 每换一批图都要手改代码
MAP = [("D2-景点-某地标.png", "d02-sight.webp"), ...]
```

✅ **新做法：命名约定驱动，零配置。**

```
图片替换/
├── D2-景点-某地标.png         → d02-sight.webp
├── D2-美食-某道菜.png         → d02-food.webp
├── D10-景点-某地标.png        → d10-sight.webp
└── D14-美食-某道菜.png        → d14-food.webp
```

解析规则：

```
D{天}-{类型中文}-{名称}.{ext}
      ↓
类型映射：美食→food / 景点→sight / 住宿→stay / 补给→charge
      ↓
目标：(day, cat)，落盘 photos/d{天:02d}-{cat}.webp
      同名已存在 → 自动递增序号（d07-sight2.webp）
```

好处：**用户只需按这个格式命名文件丢进目录**，不必懂代码、不必改 MAP。

## 五、调参指南

阈值集中在 `imgverify.py` 顶部的 `TH` 字典，也可用 `--config` 传入覆盖：

```python
TH = {
    'min_side': 480,          # 路书图位 480×640，故取 480
    'min_bytes': 20*1024,
    'ratio_lo': 0.5,
    'ratio_hi': 2.0,
    'max_text_ratio': 0.35,
    'junk_words': [...],
    'avatar_words': [...],
    'stop_words': [...],      # 泛词黑名单
    'cat_hint': {...},        # 分类词族
}
```

**调参建议**：

| 症状 | 调整 |
|---|---|
| 通过率过低（大量位无图） | 放宽 `ratio_hi` 到 2.5；或在 `junk_words` 里去掉过泛的词 |
| 仍有错配图混入 | 收紧 `cat_hint`（加更具体的词）；或为该 POI 增加更精确的 `keywords` |
| 大量攻略信息图混入 | 把 `junk_words` 命中阈值从 ≥2 降到 ≥1（需评估误伤） |
| 图片偏小 | 下调 `min_side`，但不要低于图位宽度的 1.5 倍 |

**每换一个目的地，`cat_hint` 值得过一遍** —— 高原/海岛/古城/亲子乐园的关键词
分布不同。

## 六、验收方式

```bash
# 1. 对候选清单跑判定，看逐条淘汰理由
"$PY" scripts/imgverify.py --cand cands.json

# 2. 对已落盘图片做静态扫描（尺寸/命名/字节）
"$PY" scripts/imgcrop.py --check photos/

# 3. 浏览器实测零破图
bsk evaluate --session <id> "[...document.images].filter(i=>i.naturalWidth===0).map(i=>i.src)"

# 4. 页面图片数与内容清单一致
grep -c '<figure' 路书.html   # 与预期张数比对
```

**三处都要过**才算图片模块交付完成。
