# 旅游路书制作规范 v1.0

> **用途**：作为旅游路书制作流程的参考规范文件，约束路书类产物的结构、视觉与内容。
> **标记约定**：
> - 【共性】＝ 一致遵循、已合并去重的标准，直接执行
> - 【差异】＝ 存在分歧之处，附**规范取舍**（即本规范的统一口径）

---

## 1. 结构规范

### 1.1 总体框架（五层骨架）【共性】

任何路书页面/文档均由以下五层组成，顺序固定：

```
① 报头（Hero）        行程身份：kicker / 主标题+版本 / 副题 / 导语 / 关键参数 / 更新说明
② 总览区（Overview）  3 秒总览：KPI 数据带 + 路线总览图 + 全程导航（目录或分段条）
③ 逐日行程（Days）    绝对主体：按「阶段」分组的日卡序列
④ 附录区（Appendix）  实用信息：行前必读 → 交通/补能明细 → 续航/时效口径 → 预算 → 风险 → 清单
⑤ 页脚（Colophon）    版本标识 + 数据口径声明 + 来源列表
```

层级原则：
- **逐日行程是主体**，篇幅占比 ≥50%；附录是查证工具，不抢阅读动线
- **总览先于细节**：读者不滚动页面即可回答「这是什么行程、几天、怎么走、花多少」
- **附录顺序按决策紧迫性**：硬截止事项最前，参考性数据（预算/口径）居中，风险与清单殿后

### 1.2 逐日行程的组织方式

【共性】
- 日卡按**阶段分组**（如 去程 / 环线 / 返程，或按地理区域），每组有分组头（段名 + 天数范围 + 一句话段注）
- 日卡编号连续（D1–Dn），日期链必须连续无断档（含星期）

【差异 · 日卡呈现形态】

| 形态 | 日卡默认状态 | 适用 |
|---|---|---|
| **铁路图时间轴** | 轴上收起行 + 点击展开完整卡 | **≥10 天的长行程**（默认）。兼顾节奏总览与详情，打印友好 |
| **编辑长卷** | 日卡全展开 | ≤7 天的短行程，阅读优先 |
| **分段仪表盘** | 日卡折叠为摘要卡网格 | 检索 / 比价型使用场景 |
| **地图叙事** | 日卡滚动 + 地图联动 | 重展示、轻查证的分享场景；**无 JS 约束下技术风险高，慎选** |

**规范取舍**：>10 天用**铁路图时间轴**；≤7 天用**编辑长卷**；8–10 天两者皆可，倾向铁路图。地图叙事仅在没有打印/离线需求时选用。

【差异 · 全程导航】

| 伴随形态 | 导航中枢 |
|---|---|
| 铁路图时间轴 | 轴本身即导航 + 目录条 |
| 编辑长卷 / 地图叙事 | sticky 章节目录（桌面左栏 / 移动顶条） |
| 分段仪表盘 | 分段路线总览条（可点击锚跳） |

**规范取舍**：目录条必备（低成本高收益）；分段总览条或轴导航按所选形态附带其一，不做双份。

### 1.3 日卡内部结构【共性 · 字段一个不能少】

```
日期 + 星期            例：3/15 · 周六
路线标题               A → B → C（宿点结尾）
路线串                 高速/国道编号链（G30 连霍 → G22 青兰）
一句话账               本日关键约束（续航账 / 赶路口径 / 硬截止提醒）
站点时间线             N 条：图标 + 名称 + 说明 + 类型徽章
统计条                 里程 / 纯驾驶(或在途时长) / 费用 / 住宿 / 补给（3–5 项，缺项可省但顺序不乱）
图片位                 0–2 张 3:4 竖图（分类角标 + 名称 + 一句话说明）
```

### 1.4 附录模块组成【共性】

| 模块 | 组成 | 排序原则 |
|---|---|---|
| 行前必读 | ≤5 张提示卡（分级：danger / warn / info） | 硬截止 > 落点机动 > 唯一断点 > 一般规律 |
| 交通/补能明细 | 分段折叠表（summary 显示段名 + 最长空档/关键指标） | 按行程顺序分段；默认收起 |
| 口径说明 | 折算链表格（如 实测续航→折损→安全续航）+ 配套图表 | 口径变了全篇重算，必须显式 |
| 预算 | 主表格（项目/口径/区间）+ 分档（经济/舒适/宽裕） | 合计行加粗突出 |
| 风险与降级 | 卡片（等级徽章 + 触发条件 + 降级方案） | 按「发生概率 × 不可逆性」排序；**全部展开，不许折叠** |
| 复核清单 | 分档（硬截止 / 临行 N 天 / 随车装备） | 可勾选，硬截止单独成组 |

### 1.5 信息守恒【共性 · 强制】

- 改版/改版式时建立**数量基准**（日卡数、站点数、风险数、提示卡数、表格数、图片数）并脚本化自检
- 事实数字（里程/时长/费用/日期/预约规则）逐字段与母本比对，**机器校验，不人肉抽查**

## 2. 视觉规范

### 2.1 配色

【共性】
- **低饱和双专色纪律**：每色只承担一类语义，不混用、不装饰性滥用；**禁紫色主色**
- 必备语义色：景点 / 补给(充电·餐饮) / 住宿 / 路段 / 高海拔(垭口) / 风险
- 阶段色（去程/环线/返程）**独立于**站点语义色，两套色板不得撞义
- 风险/危险只允许一个红色系，且只用于风险语义

【差异 · 四组可选配色方向】

| 方向 | 底 | 主色 | 材质 | 适用 |
|---|---|---|---|---|
| **暖沙纸** | 沙米 #FAF4E8 | 沙金 / 赭红 / 盐湖青（取自路线本身） | 暖纸 + 浮卡 | **默认**。长途自驾、打印友好、人文感与数据感兼顾 |
| **暗夜星轨** | 深蓝黑 #0B1322 | 青 #5AC8DC + 琥珀 #F2B45E | 玻璃拟态 + 发光渐变轴 | 夜间叙事、分享传播；**打印差**，路书慎用 |
| **冷灰编辑** | 冷灰白 #F4F4F1 | 单一强调色（如赭红 #C24D2C） | 大圆角 + 长柔影 | 最克制、通用；惊艳度低，不确定时的兜底 |
| **极简数据舱** | 纯白 | 黑 + 电蓝 #2E5BFF | 粗黑线 + 瑞士网格 | 数据密集型、商务感；人文感弱 |

**规范取舍**：默认**暖沙纸**（主题色从路线本身取色）；用户明确要深色/科技感时选暗夜星轨；商务报告选极简数据舱；其余不确定情形用冷灰编辑兜底。

> ⚠️ 配色方向由**用户在需求采集阶段选定**（见 SKILL.md Phase 0），不要擅自决定。

### 2.2 字体【共性】

- **三栈制**：正文衬线（书卷气）/ 标题展示衬线（Display）/ 数据与标签等宽（Mono）
- 数字一律 `font-variant-numeric: tabular-nums`，统计条对齐统一基线
- 字号下限：正文 ≥13px，标签/徽章 ≥10.5px，图注 ≥12px；**任何位置禁 <10px**
- 标题层级：H1（页面主标题，Display，clamp 流式）> H2（章节，编号 + Display）> H3（模块标签）> 卡标题（15–16px）

### 2.3 布局与留白【共性】

- 页面外壳 1060–1120px，长文阅读区 ≤880px；**栅格用 grid/flex + minmax/clamp，禁固定 px 布局**
- 卡片圆角 14–16px；阴影双级（静息 1px 浅影 / hover 或展开时 10–30px 柔影）
- 章节间距 `clamp(48px, 8vw, 96px)`，卡内间距 16/24/32 三级
- 大量留白是高级感的第一来源，**不靠堆元素填空间**

### 2.4 地图与时间线【共性 + 一条血泪差异】

- 路线示意图：**是示意不是测绘**，须在图注注明「示意，非严格地图」
- 时间线 = 竖轴 + 节点（图标 + 名称 + 说明 + 徽章）；阶段用轴色区分
- 信息图（海拔剖面/气温带/空档条形）数据必须来自台账，交付前跑**包围盒两两比对**查文字重叠
- **🔴 装饰性图形不得画得像数据**：没有真实数据拟合的曲线/图形，要么明确标注「示意」要么不画。手绘的、凭印象画的趋势线一旦被读者当成实测数据，就是一处隐性失真 —— 在一份以「可核实」为卖点的文档里，这种失真的代价远高于少画一张图。

### 2.5 图文混排【共性】

- 图片统一 **3:4 竖图成对**出现，`object-fit: cover`，任何源比例不预处理也能用（需要压缩时中心裁 3:4 + 480×640 + webp q78）
- 图卡要素：分类角标（美食/景点/住宿/补给）+ 名称 + 一句话说明（≤30 字）
- **只用真实图源，不编造、不用占位图充数**；无图的日子就不渲染图片位，不强凑
- 图片宽合计 ≤67% 栏宽并居中（铺满全宽的图显廉价）

### 2.6 图标与徽章【共性】

- 一套 **1.5px 描边线性图标**（路线/时钟/充电/景点/住宿/定位/风险/垭口等），同视图盒同描边
- 徽章：等宽字体小胶囊（10.5–11px，描边或淡底），只标类型与置信，不标观点

### 2.7 交互与动效【共性 · 无 JS 约束】

- 交互全部 CSS：`<details>/<summary>` 折叠、`:target` 锚点高亮、`position: sticky` 导航、`:hover` 微交互
- 动效时长 150–250ms，缓动 `cubic-bezier(.2,.6,.2,1)`；展开动画用 `grid-template-rows: 0fr→1fr`
- hover 抬升 2–3px + 描边提亮；**无持续动画**；`prefers-reduced-motion` 时全关
- **做不到的不伪造**：无 JS 做不到滚动监听高亮、灯箱、进度持久化——直接不做，不用 hack 冒充

### 2.8 响应式【共性 · 硬性验收】

- 验收档：**360 / 390 / 640 / 768 / 1024 / 1220 / 1440 七档零横向溢出**
- 塌陷规则：导航左栏→顶条（<1220）；多列网格→单列（<900/640）；宽表格 `table-layout: fixed` + 内部滚动；统计条→2 列（<640）
- 移动端不是缩小版，是重排版

### 2.9 可访问性【共性】

`lang="zh-CN"` / viewport / color-scheme / 信息图 `role="img"` + `<title>`/`<desc>` / `:focus-visible` 可见焦点 / 打印样式（卡片去阴影、折叠内容展开）/ 表格 th 齐全

## 3. 内容规范

### 3.1 质量总纲【共性 · 最高优先级】

**可靠性 > 完整性 > 华丽度。**
- 页面须明示：能确认「站点存在且已投运」，不保证「你去的那天它没坏、不排队」
- 易变信息（桩况/施工/放票）必须给**官方核验渠道**（省交通厅 / 12328 / 官方小程序），攻略不作数
- **时效分水岭原则**：找到该线路信息失效的时间点（如某充电站投运日），分水岭前的攻略整体排除

### 3.2 数据标注格式【共性】

| 类型 | 格式 | 示例 |
|---|---|---|
| 里程 | 整数 + km，千分位用半角空格 | `1 234 km`、`567 km` |
| 时长 | 一位小数 + h | `5.8 h`、`93 h`（合计取整） |
| 费用 | 整数元，区间用 en -dash | `¥1 234`、`5 600 – 7 800` |
| 日期 | M/D + 星期 | `3/15 · 周六` |
| 海拔 | 整数 + m，千分位空格 | `3 648 m` |
| 桩号/坐标 | 照官方格式 | `K123+000–K124+000` |
| 约数 | 「约」前置，不混用「~」 | `约 300 km` |
| 区间 | `–`（en dash），不用 `~` 或 `-` | `7 550–9 850` |

数据口径必须显式：里程/时长/费用注明测量来源与策略（如「高德 REST 驾车路径规划，速度优先，YYYY-MM-DD 实测」）；折算类数字（安全续航）给完整折算链。

### 3.3 置信度分层【共性】

| 级 | 含义 | 视觉 |
|---|---|---|
| HIGH | 多源一致（政府/官网/实测交叉） | 青绿徽章 |
| MID | 单一来源 | 琥珀徽章 |
| LOW | 仅地图 POI | 红色徽章 |
| 待核实 | 查不到 | 红色徽章 + 核验渠道提示 |

### 3.4 语言风格【共性】

- 简体中文、编辑体、克制；**陈述事实，给出判断，不煽情**
- 站点说明写「为什么停 / 注意什么」，不抄百科（好：`隧道极密集，尤溪一带长下坡，区间测速 80`；坏：`风景秀丽，是著名的旅游胜地`）
- 一句话说明 ≤30 字；续航账/提示卡可以长，但每句都要有信息量
- 禁用词：绝绝子、yyds、打卡圣地、小众秘境、宝藏、氛围感、出片率（及一切带货腔）
- 同一概念全篇同词（如「安全续航 300 km」不得又写「规划续航」）

### 3.5 各模块必备字段【共性 · 缺字段即不合格】

| 模块 | 必备字段 |
|---|---|
| 日卡 | 见 §1.3（日期/标题/路线串/一句话账/站点/统计条） |
| 交通补能行 | 站点名 / 位置 / 数量(桩数) / 功率 / 运营商 / 24h 与否 / 置信级 |
| 预算行 | 项目 / 口径注释 / 金额区间；合计行 + 人均 |
| 风险卡 | 等级 / 触发条件 / 降级方案（①②③ 可执行步骤） |
| 清单项 | 事项 / （可选）注释 em；硬截止项须带渠道与时间窗 |

### 3.6 版本与溯源【共性】

- 版本标识**四处同步**：`<title>` / 页头徽章 / 页脚 colophon / 更新说明行
- 页脚必备：编制日期 / 数据口径 / 字体与素材声明 / 来源列表（Sources）
- 更新说明行写「本次改了什么 + 仍待核实什么」，不写流水账

## 4. 形态差异与规范取舍汇总

| 维度 | 编辑长卷 | 分段仪表盘 | 地图叙事 | 铁路图时间轴 | 规范取舍 |
|---|---|---|---|---|---|
| 日卡默认 | 全展开 | 折叠网格 | 全展开+联动 | 收起行+展开 | ≥10 天选铁路图，≤7 天选长卷 |
| 导航 | sticky 目录 | 分段总览条 | 左 sticky 地图 | 轴+目录条 | 目录条必备，余者随形态 |
| 总览 | 报头+全幅图 | KPI 带+分段条 | 地图即总览 | 迷你图+轴 | KPI 带或分段条至少其一 |
| 技术风险 | 低 | 低 | 高（scroll-timeline 兼容性） | 中 | 无 JS 约束下慎选地图叙事 |
| 打印 | 最好 | 一般 | 差 | 好 | 路书默认要求打印友好 |
| 移动端 | 塌陷简单 | 塌陷简单 | 降级为静态 | 轴天然适配 | 均须七档零溢出 |

## 5. 工程约束（产出为单文件 HTML 时）【共性】

- **零外链**：无 CDN / 外链字体 / 外链图片；`<a href>` 外跳允许
- **无 JS**（或仅极少量无依赖渐进增强脚本）
- **不要求部署上线**：交付物为本地单文件 HTML，双击即可打开；构建脚本与产物**独立存在**（产物不依赖构建目录）
- 字体自托管 + 子集化：**改文案后必须重建子集**，否则新字静默回退系统字体
- 交付前自检：外链 / 脚本 / 标签闭合 / 结构数量基准 / CSS 变量完整性 / 可访问性 / 版本同步 / 数据守恒
